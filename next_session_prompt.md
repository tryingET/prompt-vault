# Prompt Vault — Stable Native Startup

This is a startup contract, not a mutable handoff, status mirror or next-task ledger.
Keep volatile direction, task state and completion evidence in their owner interfaces.

## Read first

1. `AGENTS.md` and `README.md`.
2. `docs/project/direction-workflow.md` and `docs/project/vision.md`.
3. Inspect current state before editing: `pwd`, `git status --short`, concise inventory.
4. Use native authority reads from this repo:

```bash
ak strategy list -F json
ak wave list -F json
ak direction check -F json
ak task ready -F json
ak task list -F json --verbose
```

Use the installed/gated `ak`, not removed wrappers or a checkout/cargo fallback.
Inspect the exact selected task, scope/contract, dependencies, claim and evidence
before execution. A generic continuation carries no new source-owner or lifecycle
authority. If records are missing, contradictory or blocked, report that fact;
do not import legacy documents or invent a next task.

## Current truth and ownership

- AK-native strategic frames and implementation waves own current direction;
  AK tasks/evidence own execution truth. SG/TG/OP documents are historical only.
- Inspect the live Vault with `./scripts/pv status`, `./scripts/pv migrate status`,
  `./scripts/pv templates`, `./scripts/pv skills`, and `./scripts/pv vocabulary`.
  A dirty working set is current inspectable data, not proof of released main state.
- Use `schema/client-compatibility.json` and live schema checks, not old v9-only notes.
- Prompt and skill bodies/assets remain Vault-owned; ontology defines semantics,
  not prompt bodies. Runtime binding/install/projection truth stays downstream-owned.
- Stored workflow/loop bodies, skill-import support and export eligibility are not
  proof of execution, populated skills, synchronization or adoption.
- Read the focused owner-boundary notes in `docs/dev/` when the selected task touches
  authoring, execution observability, teacher-prep or workstation machine snapshots.
- No widening workstation posture machine snapshots into a second Prompt Vault export surface.

## Execution and closure

Respect the exact scoped task and existing dirty/concurrent work. Choose discovery,
design or decision before implementation when the concern requires it. Run task/repo
validation proportional to the authorized change and distinguish past checks from
fresh proof. Do not replay completed historical waves without contrary evidence.

Record completion through native task/evidence authority only after acceptance is
met. Frame/wave closeout, promotion, publication, merge and cross-owner effects need
their own authorization. Do not rewrite this file with the latest diary pointer or
queue IDs during normal closeout; change it only when the durable startup contract
changes. Keep session narrative/learning in their declared KES surfaces.
